# Неделя 12 — обмен из vault через CLMM-пул Raydium

`configure_pool` подключает vault к пулу: проверяет, что пул принадлежит Raydium и содержит
основной токен vault, и создаёт токен-аккаунт для второго токена (`["quote_vault", vault]`).

`swap(amount_in, minimum_amount_out, sqrt_price_limit_x64)` вызывает `swap_v2` в Raydium через CPI.
Владелец токенов — PDA vault, поэтому CPI подписывается через `invoke_signed`.

## Защита от проскальзывания

| Механизм | Что делает |
|---|---|
| `minimum_amount_out` | Если получено меньше, вся транзакция откатывается |
| Обязательный минимум | `minimum_amount_out = 0` отклоняется (`MinimumOutRequired`) |
| Проверка по факту | Vault сверяет прирост баланса сам, не полагаясь только на Raydium |
| `sqrt_price_limit_x64` | Необязательный предел цены, дальше которого обмен не идёт (0 — без предела) |

## Другие проверки

- Обмен доступен только `authority`.
- Пул — только тот, что задан в `configure_pool`.
- Вход и выход — только токен-аккаунты самого vault.

## Как считаются доли

Обмен не меняет `total_assets`: это учёт внесённых средств. Если средства лежат не в основном
токене, вывод ограничен свободным остатком (`InsufficientIdleAssets`). Цена доли обновляется
после возврата средств (неделя 13).

Tick array и bitmap extension передаются через `remaining_accounts`, их список зависит
от текущей цены и направления обмена.

Инструкции Raydium собраны вручную (`raydium.rs`): дискриминатор и аргументы взяты из SDK
Raydium. Так программа не зависит от крейта, собранного под другую версию Anchor.

Тесты: `tests/week12-swap.ts`.
